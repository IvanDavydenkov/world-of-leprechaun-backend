# Локальная проверка входа через Яндекс

Нужны Go 1.26+, MongoDB Server и зарегистрированное приложение Яндекс OAuth. На текущем Windows-компьютере MongoDB найдена в Program Files; Docker для этого способа не нужен.

## Настройки приложения Яндекса

В платформе «Веб-сервисы»:

- Хост страницы с кнопкой: `http://localhost:8080`.
- Redirect URI: `http://localhost:8080/auth/yandex/callback`.
- Разрешение для данных: `login:info` — базовая информация о пользователе.

Наш backend использует серверный authorization code flow с state и PKCE S256. Redirect URI в Яндексе и в `.env` должен совпадать, включая схему, порт и путь. Путь `/login` не является callback этого backend.

Если форма Яндекса отклоняет значение поля, сначала нужно исправить настройки приложения. Не заменяйте callback отладочным verification_code: для него реализованный браузерный поток не предназначен. Для будущего продакшена нужен отдельный HTTPS callback `/auth/yandex/callback` на фактическом домене backend.

Официальные инструкции: [регистрация](https://yandex.ru/dev/id/doc/en/register-client), [authorization code и PKCE](https://yandex.ru/dev/id/doc/en/codes/code-url), [получение identity](https://yandex.ru/dev/id/doc/en/user-information).

## Подготовка и запуск на Windows

Из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Start-Local.ps1 -PrepareOnly
```

Скрипт создаёт игнорируемый Git файл `.env` и заполняет пустые пароли MongoDB и ключ шифрования случайными значениями. Уже заданные значения сохраняются. Добавьте в `.env` данные приложения, не отправляя Client Secret в чат:

```dotenv
YANDEX_CLIENT_ID=<Client ID приложения>
YANDEX_CLIENT_SECRET=<Client Secret приложения>
YANDEX_REDIRECT_URL=http://localhost:8080/auth/yandex/callback
```

Затем:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Start-Local.ps1
```

Скрипт запускает отдельную MongoDB на `127.0.0.1:27018`, базу `users_local`, и users API на `127.0.0.1:8080`. Данные и журналы находятся в `.local/`, вне Git. Для этого локального режима MongoDB работает без аутентификации и доступна только через loopback. Не используйте эту конфигурацию для публичного сервера. Производственный Compose продолжает использовать разные учётные записи MongoDB.

Откройте `http://localhost:8080/`, нажмите «Войти через Яндекс». После согласия Яндекс вернёт браузер на callback, backend создаст пользователя и сессию, затем перенаправит на `/me`. Там будут `id`, `yandex_id`, `display_name`, `role`. Токен Яндекса и токен сессии в JSON не выдаются.

Сессия живёт 24 часа и хранится в HttpOnly / SameSite=Lax cookie. На localhost cookie без Secure, на HTTPS — Secure с префиксом __Host-. В MongoDB хранится только хеш непрозрачного токена сессии; state одноразовый и действует 10 минут. Роль пересчитывается по актуальной конфигурации при каждом запросе.

Чтобы проверить admin, скопируйте собственный `yandex_id` из `/me` в `ADMIN_YANDEX_ID` в `.env` и повторно запустите скрипт. Вашу уже существующую сессию удалять не нужно: после перезапуска `/me` покажет новую роль. Проверка каталога пользователей — `GET /admin/users?limit=50&after=<last-id>`, только для admin. Число VPN-конфигов в каталог пока не добавлено.

Выход доступен кнопкой на главной странице. POST `/auth/logout` проверяет Origin и удаляет текущую серверную сессию. Для ручного HTTP-вызова нужен `Origin: http://localhost:8080` и cookie сессии.

Если ID и Secret ещё пустые, users запускается для проверки health/readiness, но главная страница возвращает 503 с инструкцией включения OAuth. Частично заполненная конфигурация считается ошибкой старта.

Изменения `.env` применяются после повторного запуска скрипта. API пересобирается и перезапускается, MongoDB и данные сохраняются. Скрипт управляет только записанными им процессами с совпадающими PID, путём и временем запуска.

Остановка локальных процессов:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Stop-Local.ps1
```

## Альтернатива через Docker

При установленном Docker и заполненном `.env` можно запустить только необходимые сервисы:

```powershell
docker compose up --build -d mongodb users
```

Не запускайте одновременно нативный users и Compose users на порту 8080. В нативном варианте данные в users_local, в Compose — в users; это разные локальные профили.

## Что проверить

1. `GET /healthz` и `/readyz` возвращают 200.
2. `/me` без входа возвращает 401.
3. Первый вход создаёт обычного user, повторный возвращает тот же ID.
4. Попытка открыть `/admin/users` обычным пользователем возвращает 403.
5. После настройки ADMIN_YANDEX_ID и перезапуска `/me` возвращает admin.
6. Выход делает прежнюю cookie недействительной.

Автоматические тесты проверяют state, PKCE, повтор callback, истечение сессии и утрату административных прав. Модульные тесты провайдера имитируют Яндекс; реальное согласие пользователя и настройки приложения проверяются только в браузере. VPN-хост для проверки авторизации не требуется.
