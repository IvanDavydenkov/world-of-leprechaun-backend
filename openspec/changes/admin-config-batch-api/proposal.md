# Пакетная выдача и удаление VPN-конфигов

## Why
Администратор должен одной операцией выдать пользователю указанное количество новых конфигов и иметь возможность отозвать один, несколько выбранных или все конфиги.

## What Changes
- POST /admin/users/{user_id}/configs: JSON count от 1 до 20, создание именно новых записей и peer.
- DELETE /admin/users/{user_id}/configs/{config_id}: отзыв одного.
- POST /admin/users/{user_id}/configs/bulk-delete: отзыв явно выбранных ID.
- DELETE /admin/users/{user_id}/configs: отзыв всех текущих конфигов и незавершённых выдач пользователя.
- GET /admin/users/{user_id}/config-operations/{operation_id}: результат долговечной операции с детализацией по элементам.

## Capabilities
### New Capabilities
- admin-config-batch-api: HTTP-контракт пакетных административных операций.

## Impact
Используются существующие сценарии admin-config-management, сессии users, шифрование файлов и SSH Provisioner vpn-configs. Нужна долговечная родительская операция с дочерними намерениями и защита межсервисных запросов. История расхода сохраняется согласно admin-user-overview.

## Approval
Статус: ОДОБРЕНО пользователем. Реализация HTTP, очереди и обработчика выполнена; реальная проверка тестового peer ожидает настроенного хоста.

Пользователь подтвердил:
- count означает число новых конфигов, а не желаемое итоговое количество;
- диапазон count: 1..20 за запрос, без общего лимита на пользователя;
- удаление одного, выбранных и всех конфигов.

Одобрены маршруты, ответ 202 с operation_id, поэлементные результаты при частичных сбоях, обязательный Idempotency-Key и повтор только незавершённых элементов.

## Out of Scope
Автоматическое назначение существующих неназначенных peer вместо создания новых, восстановление удалённых вместо выдачи новых, пауза, лимиты подписки и удаление истории расхода.
