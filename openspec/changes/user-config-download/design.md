# HTTP-контракт и изоляция владельца

GET /me/configs возвращает 200 и массив [{"id":"config-id","name":"Phone","status":"active","version":1,"created_at":"2026-10-15T12:00:00Z","download_available":true,"download_url":"/me/configs/config-id/download"}]. Если своих активных конфигов нет, возвращается [].

В список попадают только подтверждённые active записи владельца из сессии. Deleted, creating, deleting, reactivating и неназначенные peer не выдаются. download_available означает наличие файла для текущего поколения; при отсутствии файла download_url=null. Файлы, ключи, ciphertext и данные подключения SSH в список не включаются.

GET /me/configs/{config_id}/download возвращает байты расшифрованного .conf из MongoDB без запроса к VPN-хосту. Content-Type: application/octet-stream; Content-Disposition: attachment; filename="config-<config_id>.conf". Имя файла строится из проверенного ID, не из произвольного названия.

401 — нет действующей сессии. 404 — конфиг отсутствует, принадлежит другому владельцу, не active или файл текущего поколения недоступен. Причины 404 не различаются публично. 503 — недоступно хранилище или внутренний сервис. Невалидный ID отклоняется без обращения к файлу.

Оба маршрута доступны и user, и admin, но только для собственных конфигов. Нет административного исключения из проверки владельца. user_id/owner_id в query, теле и недоверенных заголовках не влияют на владельца. Перед скачиванием VPN-сервис повторно проверяет ownership и текущее состояние. После начатого отзыва дальнейшие скачивания блокируются; уже переданный клиенту файл отозвать из памяти браузера нельзя.

Межсервисные запросы требуют сервисного токена. users передаёт идентичность, полученную из сессии, а не входящие X-Actor-ID/X-User-ID. vpn-configs проверяет действительность пользователя через users и выбирает записи только его аккаунта. Содержимое расшифрованного файла не логируется и не передаётся через URL.

Ответы: Cache-Control: no-store, X-Content-Type-Options: nosniff. Защита сессионной cookie сохраняется. Проверка идентичности и владельца обязательна даже при прямом обращении к внутреннему VPN API.
