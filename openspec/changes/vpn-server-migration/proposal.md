# Переключение VPN-серверов без автоматического отзыва выдач

## Why
При блокировке одного VPN-хоста администратор переключает пользователей на подготовленный другой. Прежний сервер остаётся арендованным, его конфиги должны продолжать действовать и быть повторно использованы при возвращении. Подготовка Ubuntu-хоста и установка нашего helper выполняются через сайт; аренду и установку Amnezia администратор выполняет вручную.

## What Changes
- Реестр серверов становится источником настроек подключения; рабочие VPN env заменяются однократным идемпотентным импортом.
- Подготовка сервера через admin API: проверка доверенного SSH-ключа, discovery AmneziaWG, установка/обновление версионированного helper, проверка готовности.
- У постоянного пользовательского конфига есть независимые выдачи на нескольких серверах и указатель на выбранную для скачивания.
- Одно действие переключает default для новых выдач и запускает переключение всех активных пользовательских конфигов на target.
- Существующие действующие выдачи target проверяются и используются повторно; отсутствующие/подтверждённо отозванные создаются. Недоступность source не мешает переключению.
- Ни переключение, ни подготовка, ни смена default не отзывают старые peer, не удаляют файлы, не останавливают серверы и не прекращают аренду.
- Отзыв на одном сервере или на всех серверах — отдельные явные административные операции.

## Approval
Семантика ОДОБРЕНА пользователем 2026-11-02. Пользователь попросил завершить спецификацию и передать её агенту фронтенда. Этот пакет описывает целевой контракт для согласованной реализации; backend-маршруты, подготовка через сайт, переключение и CLI импорта реализованы локально и проверены тестами; rollout production и frontend выполняются отдельно. API реестра POST/GET/PATCH реализован отдельно в vpn-server-registry.

## Supersedes
Этот текст полностью заменяет предыдущий проект одноразовой миграции в том же каталоге. Не использовать прежние vpn-migrations, source_server_id как обязательный параметр, superseded как признак отзыва или автоматический cleanup. Неназначенные peer и импорт чужих ключей остаются отдельной задачей.

## Deliverables
Читайте README.md, api-contract.md и frontend-handoff.md. design.md описывает модель и инварианты; tasks.md разделяет backend/frontend и проверки.

## Out of Scope
Аренда VPS, установка Docker/AmneziaWG с нуля, оплата серверов, обход блокировок, автоматическое изменение конфигов на устройствах, уведомления, восстановление утраченного трафика, импорт неназначенных peer. Поддерживается Ubuntu с уже установленным приложением Amnezia контейнерным AmneziaWG. Версии/форматы вне поддерживаемого диапазона отклоняются безопасно.
