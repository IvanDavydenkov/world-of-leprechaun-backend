# VPN-серверы в MongoDB и миграция с перевыпуском

## Why
Адрес и учётные данные единственного VPN-хоста сейчас читаются из env при запуске. Для смены серверов нужны записи серверов в MongoDB, привязка поколений конфигов к исходному хосту и управляемый перевыпуск без доступа к старому серверу.

## What Changes
- Административный реестр VPN-серверов с зашифрованным SSH-паролем и закреплённым ED25519-ключом.
- Один выбранный сервер для новых выдач; уже созданные поколения и операции сохраняют свой server_id.
- Миграция active конфигов на новый сервер с сохранением config_id и владельца, новыми ключами и новым файлом.
- Сохранение истории поколений и независимый учёт отзыва старых ключей.
- Однократный явный импорт текущей env-конфигурации и привязка существующих записей; без обязательного повторного ввода.

## Approval
Пользователь подтвердил направление: новый сервер с перевыпуском конфигов, а не перенос исходных ключей. Детальный контракт этого изменения — ЧЕРНОВИК ДЛЯ ОДОБРЕНИЯ; код пока не меняется.

## Impact
Изменяются domain/application/infrastructure vpn-configs, выбор Provisioner по server_id, MongoDB-адаптеры и административные маршруты users. Ключ шифрования, MongoDB, Yandex OAuth и межсервисный токен остаются в окружении. SSH-пароли хранятся только как ciphertext; ответы и логи их не содержат.

## Out of Scope
Создание VPS через провайдера, автоматическая установка Amnezia на чистую Ubuntu, перенос серверного приватного ключа, восстановление утраченного трафика, реализация сборщика трафика, пользовательские уведомления, импорт неназначенных peer. Новый сервер должен иметь совместимую AmneziaWG и helper; проверка выявляет отсутствие/несовместимость. Опасный обход проверки SSH-ключа не допускается.
