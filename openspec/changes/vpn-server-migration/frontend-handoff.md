## Страница/раздел «Серверы VPN» (только admin)
Для каждого сервера: название, SSH address, public VPN endpoint (или «Будет определён»), container/interface, preparation_status, время последней проверки, helper version, is_default и binding counts. Показывать «Выбран для новых выдач», а не «Все устройства подключены сюда». Не утверждать ready при отсутствии новых полей в старом DTO. Пользовательская роль не видит настройки/пароли и не может открыть экран по URL; server-side authorization обязательна.

Кнопки:
- «Добавить сервер»: имя, SSH address с портом, SSH username/password, доверенный ED25519 fingerprint ИЛИ full public key; public_host, если отличается/не определён. Container/interface/UDP не обязательны в новом контракте — discovery после сохранения. Не менять форму старого backend до поддержки нового POST.
- «Проверить и подготовить»: async prepare, отдельные шаги, не просто spinner до первого 202. Нужна объясняющая строка «Ubuntu и Amnezia должны быть уже установлены. Будет установлен или обновлён helper; пользовательские ключи не меняются».
- При needs_input показать полученные кандидаты/container/interface/порты и отправить resume. Не предлагать ввод произвольных shell-команд и не угадывать кандидата.
- «Переключить пользователей сюда»: доступна только для ready target, текущего routing revision и отсутствия активного switch. Создаёт одну операцию, без дополнительной ручной смены default. Для текущего default тоже допустима: доводит оставшиеся элементы после смешанного состояния.
- «Отозвать выдачи этого сервера»: отдельное опасное действие, не часть switch. Нельзя для default/выбранных пользователями bindings — backend вернёт server_in_use. UI объясняет сначала переключить пользователей. Никакой автоочистки/автоотзыва.

На мобильном — вертикальные карточки/полноэкранная форма и компактный прогресс; на desktop — таблица или широкие карточки и модалка. Соблюдать mobile-first, читаемые ошибки и отсутствие горизонтального скролла. Не менять дизайн всего кабинета в рамках этой задачи.

## Один клик переключения
После предварительной подготовки target нажатие запускает POST /admin/vpn-switches. Достаточно видимого пояснения непосредственно рядом с действием: «Старые конфиги останутся рабочими. Файлы в кабинете изменятся. Пользователям нужно заново скачать и импортировать конфиг». Дополнительная ручная установка helper, правка env или выбор source не нужны. Не встраивать обязательный многократный wizard/confirm для каждого последующего возврата A→B→A. Опасный отзыв требует отдельного подтверждения с сервером и областью.

UI показывает: target, default server, фаза planning/processing, requested/succeeded/failed/pending/skipped, число created/reused/already_selected по загруженным элементам (не выдавать неполную страницу за глобальную сводку). counts=null означает «План формируется», не 0. Успех только по status=succeeded, 202 — лишь принятие. При partial/failed показать успешные и ошибочные элементы, кнопку retry если backend retryable, и что успешные элементы не откатились. Если operation неуспешна, текущий default всё равно читать из routing, не возвращать старое значение локально.

Подробности элементов загружаются постранично через /items, а не безлимитным массивом в каждом poll. На ошибку отдельного пользователя не обнулять остальные результаты.

## Polling, повторы и перезагрузка
Начальный интервал polling 2 секунды для queued/running; пауза/остановка при needs_input и terminal. При скрытой вкладке снизить частоту; при возврате refetch. Сетевой таймаут и 503 не переводят operation в failed: показать «Не удалось получить статус» и повтор запроса статуса. Обновлять список серверов/routing/admin users/my configs после завершения/при возвращении в кабинет, без утечки кэша между пользователями.

Idempotency-Key генерируется для каждого намерения и сохраняется при неизвестном исходе. Двойной клик блокируется. Тот же payload после потерянного 202 повторяется с прежним ключом; сохранять можно только не содержащие секретов operation_id/key/payload (switch/retry), в sessionStorage с очисткой при logout. Пароли в sessionStorage/localStorage/Redux actions/state/devtools/логах не сохранять; сохранить существующий защищённый способ одноразовой передачи из формы. После 202 prepare секреты в UI очищены; восстановление идёт по безопасному списку операций. Обновление страницы не запускает новый switch автоматически.

retry — отдельный POST, новый ключ; успешно завершённые items не пересоздаются. switch_superseded означает обновить routing и предложить новое осознанное действие вместо повторения старого. revision_conflict — refetch, не тихая перезапись expected_revision и автоматическое исполнение.

401 — обновить сессию/отправить на вход, 403 — доступ запрещён, 409 — конкретное объяснение конфликта, 503 — временная недоступность. raw SSH stderr никогда не отображается. Все коды и DTO — api-contract.md.

## Удаление и кабинет пользователя
Существующие кнопки удаления одного/нескольких/всех конфигов теперь явно предупреждают «Отозвать доступ на всех серверах». Их нельзя переиспользовать как очистку прошлого сервера при switch. Для scope=server используется отдельный endpoint и отдельная модалка подтверждения.

Кабинет продолжает показывать один элемент на config_id и скачивать /me/configs/{id}/download. Standby выдачи не становятся дополнительными конфигами и не увеличивают лимиты/счётчики. Пользователь не выбирает произвольный server_id через query. После смены version показывать актуальные данные; не обещать автоматически перенастроенный Amnezia-клиент. Если пользователю не добавлен собственный механизм уведомления/подтверждения импорта, UI не должен утверждать, что он уже перешёл.

## Приёмка frontend
- Admin-only экран и прямые URL, обычный user не видит управление.
- A→B создаёт B, A остаётся действовать; B→A использует reused без сообщения об отзыве B.
- Третий сервер добавляется/готовится тем же сценарием.
- Статусы not_prepared/preparing/needs_input/ready/failed/stale и безопасный выбор discovery.
- 202 не успех; polling queued/running, needs_input, terminal; partial, retries, неизвестный результат и перезагрузка.
- Конфликты routing/server revisions, server_in_use, недоступный старый сервер, ошибочный target.
- Не возникает неявных POST revoke/DELETE при переключении.
- Явный отзыв требует подтверждения; текущий/default сервер не отзывается через server scope.
- Старый backend/404/capabilities=false блокирует новые действия, не маскируется моками.
- Пароль не появляется в Redux/state/actions, persistent storage, URL, логах или ответах; fingerprint не заменяется автоматически.
- Проверить mobile/desktop, typecheck, Vitest/RTL, production build. Проверки backend нужны отдельно: успешный UI-тест не доказывает установку helper или реальную смену VPN.
