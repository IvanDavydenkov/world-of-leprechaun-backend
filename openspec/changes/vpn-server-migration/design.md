# Реестр серверов и миграция

## Модель
vpn_servers: id, name, ssh_address (host:port), ssh_username, encrypted_password, ssh_host_key (проверенный ED25519 public key), public_endpoint (host:UDP port), container, interface, revision, created_at, updated_at. Настройки контейнера/интерфейса передаются helper как валидированные данные, а не shell-код; текущие жёстко заданные значения адаптера нужно убрать. Сам helper и формат установки должны быть совместимы с проверкой версии.

Отдельная singleton-запись маршрутизации содержит default_server_id и revision. Выбор default атомарен; новый default влияет только на новые операции. Изменённые параметры сервера требуют новой проверки подключения. Проверка привязана к revision; нельзя выбрать сервер, проверенный до изменения настроек. Секрет шифруется AES-GCM с отдельным контекстом назначения, привязкой к server_id и версией ключа; plaintext не хранится и не возвращается. В env остаётся мастер-ключ, имеющийся ключ конфигов не удаляется и не меняется молча.

Поколение: generation_id, config_id, owner_id, server_id, remote_id, состояние provisioning/active/superseded/revoking/revoked, ссылки на файл и сохранённую историю. Текущая запись конфига содержит указатель на выбранное поколение и version. Ранее сохранённые файлы не перешифровываются под новым server_id без необходимости. Файлы старых поколений не доступны через пользовательский download.

Операция фиксирует server_id и generation_id до первого удалённого вызова. Повторы не используют изменившийся default и не создают новое поколение. Смена адреса/пароля допустима как обслуживание того же хоста; подмена новой установкой запрещена — создаётся новый server_id. Пока есть выполняющаяся операция, изменение подключения блокируется 409. Записи серверов с историей не удаляются физически. Контекст ключа helper на новом хосте не заменяется автоматически.

## API администратора
Все публичные маршруты на users, проверяют актуальную admin-сессию; изменения также проверяют Origin. VPN-сервис требует сервисный токен и проверяет текущую роль.

- GET /admin/vpn-servers — массив безопасных метаданных, password_set, is_default, connection_status; без пароля и ciphertext.
- POST /admin/vpn-servers — добавить запись (name, ssh_address, ssh_username, password, ssh_host_key, public_endpoint, container, interface); 201.
- PATCH /admin/vpn-servers/{id} — изменить с expected_revision; пропущенный password сохраняет прежний, пустой отклоняется; 409 при конфликте.
- POST /admin/vpn-servers/{id}/check — проверить SSH-ключ, авторизацию, Docker, установку/версию AWG, helper и указанный интерфейс. Чтение без создания/отзыва peer; безопасный результат без секретов.
- PUT /admin/vpn-servers/default с {"server_id":"..."} — выбрать проверенный сервер для новых выдач.
- POST /admin/vpn-migrations с {"source_server_id":"...","target_server_id":"..."} и Idempotency-Key — 202, migration_id.
- GET /admin/vpn-migrations/{id} — прогресс выдачи и очистки старого сервера отдельно, результаты по config_id, безопасные коды ошибок.
- POST /admin/vpn-migrations/{id}/retry — повторить незавершённые элементы с прежними поколениями; 202.
- POST /admin/vpn-migrations/{id}/revoke-old с Idempotency-Key — явный отзыв старых поколений для успешно переключённых записей; 202. Успех скачивания файла пользователем не означает успешный импорт/подключение.

Недействительная сессия 401, недостаточные права 403, неверные поля 400, отсутствующая запись 404, конфликт 409, зависимость недоступна 503. Ответы no-store. Выдача/очистка долговечны, с lease, fencing и поэлементными повторами. Новый запрос с тем же ключом и другим payload даёт 409.

## Миграция
Выбор нового default — отдельное явное действие администратора. При старте миграции source не должен оставаться default, target должен быть проверен; старт и смена default сериализуются. План строится долговечно и восстанавливается после сбоя. Переносятся только active конфиги текущего source. Deleted и pending записи не восстанавливаются. Если на source есть незавершённые выдачи/реактивации, старт возвращает 409: сначала завершить либо отозвать их, чтобы не потерять позднюю выдачу. Конкурентные миграции одного конфига запрещены.

Для каждого config_id резервируется ровно одно новое generation_id на target. Создаётся peer, файл шифруется и сохраняется, после чего CAS переключает указатель на новое поколение и увеличивает version. До успешного переключения прежний файл остаётся доступным; ошибка нового сервера не уничтожает прежнюю выдачу. Общая миграция не является атомарной для всех пользователей — возможен частичный успех.

Удаление имеет приоритет: после регистрации удаления миграция не может вернуть конфиг в active. Если новый peer уже создан, но переключение не состоялось, очередь обязана отозвать его. Удаление одного/всех конфигов учитывает все ещё действующие поколения на всех серверах. При недоступном старом сервере не объявляется подтверждённый deleted до отзыва; новые скачивания блокируются сразу. Требуется отдельная проверка гонок с revoke-all и восстановлением worker.

После переключения исходное поколение superseded, но не считается отозванным. На новом файле меняются ключи и endpoint; пользователь должен скачать и импортировать его заново. Повторный запрос миграции не увеличивает число постоянных конфигов.

Статусы выдачи: pending/running/succeeded/partial/failed. Отдельно cleanup_status: not_requested/pending/running/succeeded/partial/blocked. Недоступность source не мешает перевыпуску, но не подтверждает отзыв. Старые peer продолжают учитываться как неотозванные. Для диагностики сохраняются server_id/generation_id и результаты отзыва; приватные ключи в DTO не входят.

История расхода остаётся привязанной к поколениям и владельцу; миграция не копирует байты как новое начисление и не удаляет имеющиеся записи. Сбор трафика пока не реализован: отсутствие показаний обозначается unavailable, потерянные данные не выдумываются.

## Переход с env
Явная одноразовая команда dry-run/import читает локальные настройки, сохраняет сервер с зашифрованным паролем и проверенным ключом, затем идемпотентно привязывает существующие конфиги/поколения/операции к этому server_id. Нужны план, счётчики и checkpoint. На время применения приостановлены worker и изменяющие конфиги запросы; чтение и скачивание допускаются. Переход не создаёт и не отзывает peer, не меняет файлы и не требует новой авторизации пользователей.

После проверки миграции источником истины становится БД; отсутствующие записи дают явную ошибку, а не скрытый fallback в env. Локальные env-переменные хоста удаляются только после успешного переноса. Импорт не выполняется автоматически при каждом запуске.

## Бэкап
Резервировать MongoDB и мастер-ключ отдельно. Без ключа нельзя восстановить пароли/файлы. Резервирование серверного состояния и helper journal полезно, но не является условием перевыпуска на новом хосте. Возможность перевыпуска без старого хоста не означает возможность подтвердить отзыв старых ключей.
