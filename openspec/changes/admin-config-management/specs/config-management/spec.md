## ADDED Requirements

### Requirement: Administrator creates remote configs
Система SHALL позволять admin создавать новый конфиг на VPN-хосте для существующего пользователя; конфиг становится доступным только после подтверждённого создания.

#### Scenario: Create for registered user
- **WHEN** admin создаёт конфиг существующему пользователю
- **THEN** после подтверждения хоста конфиг появляется только у указанного владельца

#### Scenario: Unknown target
- **WHEN** целевой пользователь не существует
- **THEN** удалённый конфиг не создаётся

#### Scenario: Repeated creation request
- **WHEN** повторяется запрос с тем же ключом идемпотентности
- **THEN** возвращается та же операция без создания второго конфига

#### Scenario: Unknown remote result
- **WHEN** связь прерывается после возможного создания на хосте
- **THEN** система сверяет удалённое состояние перед повтором и не объявляет успех без подтверждения

### Requirement: Revoke individual config
Система SHALL позволять только admin отзывать конфиг на VPN-хосте и помечать запись deleted только после подтверждения отзыва; запись сохраняется в БД.

#### Scenario: Confirmed revocation
- **WHEN** хост подтверждает отзыв
- **THEN** ранее выданный конфиг больше не даёт VPN-доступ
- **AND** конфиг отсутствует в активном списке владельца
- **AND** запись сохранена в БД с отметкой и временем удаления

#### Scenario: Host unavailable
- **WHEN** отзыв не подтверждён из-за ошибки хоста
- **THEN** операция остаётся незавершённой с возможностью повтора
- **AND** приложение не выдаёт конфиг для скачивания
- **AND** система не утверждает, что ранее скачанный конфиг уже отключён
- **AND** запись не помечена deleted

### Requirement: Reactivate a deleted record
Система SHALL позволять только admin повторно активировать удалённую запись, сохраняя config_id и создавая новую выдачу с новыми ключами и файлом.

#### Scenario: Successful reactivation
- **GIVEN** конфиг отозван на хосте и помечен deleted в БД
- **WHEN** admin активирует запись
- **THEN** на хосте создаётся новая выдача
- **AND** в прежней записи обновляется ссылка на зашифрованный файл и увеличивается версия
- **AND** ранее скачанный файл остаётся недействительным

#### Scenario: Old revocation result arrives late
- **WHEN** приходит повторное подтверждение отзыва прежней выдачи
- **THEN** оно не помечает новую выдачу удалённой

### Requirement: Encrypted configuration files
Система SHALL хранить скачиваемые файлы в MongoDB зашифрованными, с ключом вне БД в окружении vpn-configs; активная выдача доступна только после сохранения файла.

#### Scenario: Download from profile
- **WHEN** владелец скачивает актуальный активный конфиг
- **THEN** файл расшифровывается из MongoDB без обращения к VPN-хосту

#### Scenario: File persistence fails
- **WHEN** создание на хосте подтверждено, но файл не сохранён
- **THEN** конфиг не публикуется для скачивания
- **AND** повтор использует ту же выдачу без создания второго peer

#### Scenario: Ciphertext copied to another owner
- **WHEN** зашифрованные данные подменены файлом другого владельца или выдачи
- **THEN** проверка целостности отклоняет расшифровку

### Requirement: Revoke all user configs
Система SHALL позволять только admin отзывать все конфиги пользователя, учитывать незавершённые создания и блокировать новую выдачу до завершения массовой операции.

#### Scenario: Revoke all
- **WHEN** все отзывы подтверждены и неопределённых созданий не осталось
- **THEN** операция завершена и пользователь имеет ноль активных конфигов

#### Scenario: Partial failure
- **WHEN** часть отзывов успешна, а часть завершилась ошибкой
- **THEN** успешные отзывы сохраняются
- **AND** общий результат не помечается успешным
- **AND** повтор обрабатывает незавершённые отзывы безопасно

#### Scenario: Creation overlaps revocation
- **WHEN** массовый отзыв начинается при незавершённом создании
- **THEN** результат создания учитывается и при наличии отзывается до завершения массовой операции

#### Scenario: Issue after completion
- **WHEN** admin создаёт новый конфиг после завершённого массового отзыва
- **THEN** создание разрешено без разблокировки аккаунта

### Requirement: Owner access
Система SHALL разрешать обычному пользователю только просмотр и скачивание собственных активных конфигов; создание и удаление конфигов доступны только admin.

#### Scenario: Another owner's config
- **WHEN** пользователь запрашивает чужой конфиг
- **THEN** содержимое не выдаётся
