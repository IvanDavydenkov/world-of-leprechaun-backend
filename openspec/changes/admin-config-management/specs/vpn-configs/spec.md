## MODIFIED Requirements

### Requirement: Metadata persistence
MongoDB SHALL хранить метаданные, состояние мягкого удаления, поколение и версию выдачи, а также зашифрованный скачиваемый файл; ключ шифрования хранится вне БД.

#### Scenario: Metadata listing
- **WHEN** читается список конфигов
- **THEN** приватные ключи и расшифрованные файлы не требуются

#### Scenario: Deleted record
- **WHEN** VPN-хост подтвердил отзыв
- **THEN** запись сохраняется с отметкой deleted и не доступна пользователю для скачивания

### Requirement: Multiple configs
Модель SHALL поддерживать ноль, один или несколько активных конфигов пользователя; отдельного числового лимита нет, число доступных конфигов равно числу активных назначений.

#### Scenario: New profile
- **WHEN** обычный пользователь впервые зарегистрирован
- **THEN** число доступных конфигов равно нулю

#### Scenario: No configs
- **WHEN** запрашиваются конфиги пользователя без назначений
- **THEN** возвращается пустой список

#### Scenario: Successful creation
- **GIVEN** пользователь имеет два активных конфига
- **WHEN** admin успешно создаёт ему ещё один
- **THEN** число доступных конфигов становится три

#### Scenario: Pending operation
- **WHEN** создание ещё не подтверждено либо конфиг отзывается
- **THEN** такая запись не входит в число доступных конфигов
