# Управление ролями и конфигами пользователя

## Why
Публичная регистрация должна давать только доступ к собственному пустому профилю. Владелец проекта вручную выдаёт VPN-доступ, создавая конфиги на удалённом сервере, и может отозвать отдельный конфиг либо все конфиги пользователя.

## What Changes
- Ровно две роли: user и admin; модераторов нет.
- Новый обычный пользователь имеет ноль конфигов.
- Отдельного числового лимита нет: число доступных конфигов равно числу активных назначенных конфигов.
- Только admin создаёт новые конфиги на VPN-хосте для зарегистрированного пользователя.
- Только admin удаляет один или все конфиги пользователя с обязательным отзывом VPN-доступа.
- Пользователь видит и скачивает только собственные активные конфиги.

## Capabilities
### New Capabilities
- admin-access: единственный администратор, серверная проверка роли.
- config-management: создание, отзыв и массовый отзыв с обработкой сбоев.

### Modified Capabilities
- vpn-configs: вместо отдельного лимита используется фактическое число активных конфигов.

## Impact
users отвечает за identity и определение роли. vpn-configs отвечает за принадлежность конфигов, их жизненный цикл и удалённые операции. Прямого доступа к чужой базе нет. Потребуются защищённый API, доверенное подтверждение роли между сервисами и адаптер VPN-хоста.

## Approval
Статус: ОДОБРЕНО пользователем; реализация начата. Последующие уточнения о мягком удалении, повторной активации с новыми ключами и зашифрованном файле в MongoDB также подтверждены пользователем.

Подтверждено пользователем:
- отдельного лимита нет;
- добавление означает создание нового конфига на VPN-сервере;
- удаление означает отзыв VPN-доступа и удаление из профиля.
- запись в БД сохраняется с отметкой deleted только после подтверждённого отзыва;
- повторная активация создаёт новую выдачу с новыми ключами и файлом в прежней записи;
- файл хранится в MongoDB зашифрованным, ключ хранится в окружении VPN-сервиса;
- VPN-хост: Ubuntu, доступ по SSH, AmneziaWG установлен через приложение Amnezia.

Одобрены также:
- единственный admin определяется по точному Yandex ID из ADMIN_YANDEX_ID;
- обычный пользователь не создаёт и не удаляет конфиги самостоятельно;
- удалить все означает удалить текущие конфиги, не блокируя последующую выдачу;
- операция удаления всех временно запрещает создание новых конфигов для этого пользователя;
- при ошибке отзыва операция остаётся незавершённой и доступна для безопасного повтора.

## Out of Scope
Модераторы, тарифы, квоты, оплата, самостоятельная выдача конфигов пользователем, импорт готовых конфигов, удаление аккаунта. Протокол управления Amnezia требует отдельного уточнения перед реализацией удалённого адаптера.
