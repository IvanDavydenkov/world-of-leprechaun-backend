# OpenSpec проекта

Инициализирован официальным CLI: openspec init --tools none. Это требования и процесс изменений OpenSpec; HTTP-контракт OpenAPI пока не создавался.

Спецификации описывают согласованное целевое поведение. Текущий статус:
- Реализованы: два сервиса, чистая архитектура, Docker Compose, MongoDB-адаптеры, отдельные базы и учётные записи, индексы, /healthz и /readyz.
- Репозитории ещё не вызываются из бизнес-HTTP: авторизация отсутствует.
- Не подключены к executable: Yandex OAuth, сессии, административный HTTP API и SSH-адаптер; состояние новых бизнес-сценариев описано ниже.
- Проверка реальной MongoDB и Compose в этой среде не выполнялась: Docker отсутствует.

Новые изменения оформляются в changes/<name>/ с proposal.md, design.md, tasks.md и дельтами specs/<capability>/spec.md. После реализации и проверки — архивирование через CLI.

Проверка: npm exec --yes --package=@fission-ai/openspec -- openspec validate --all --strict

Открытые вопросы: точная версия и контейнер VPN-хоста, сессии и межсервисное доверие, HTTP-контракт. Права admin и жизненный цикл согласованы в активном изменении ниже.

## Изменение admin-config-management

Пользователь одобрил модель единственного admin по Yandex ID, создание конфигов через личный кабинет, отзыв одного/всех, мягкое удаление и повторную активацию с новыми ключами и файлом в прежней записи. Файл хранится зашифрованным в MongoDB. Хост: Ubuntu, SSH, AmneziaWG, установленный приложением Amnezia.

В application реализованы политика ролей, каталог пользователей с проверкой admin, очередь операций, мягкое удаление, повторная активация, история для admin и скачивание через зашифрованное хранилище. MongoDB-адаптеры поддерживают CAS метаданных и отдельное хранилище ciphertext. Модульные тесты проходят.

Users HTTP теперь поддерживает Yandex OAuth с state/PKCE, серверные MongoDB-сессии, /me, /auth/logout и /admin/users. Пользователь подтвердил успешный реальный OAuth-вход локально. Интеграционные тесты хранилищ прошли на локальной MongoDB.

Одобренное изменение admin-config-batch-api подключает пакетные HTTP-маршруты, проверку роли между сервисами и фоновый обработчик. Публичный API находится на users, VPN API требует сервисный токен. Пачка сохраняется одним CAS; дочерние операции имеют lease, безопасные повторы и поэлементные результаты. Локально запущены оба сервиса, прошли HTTP/application/MongoDB-тесты с имитацией хоста.

Реальное создание/отзыв на сервере не проверялись: нужно установить root-helper и настроить проверенный known_hosts. Новый запрос при несконфигурированном Provisioner отклоняется с 503. Изменения остаются активными и не архивированы. admin-user-overview со статистикой и неназначенными peer остаётся отдельным неисполненным черновиком; его одобрение не подразумевается одобрением пакетного API.
